# Решения и границы PoC

## Текущий режим: без отдельного backend

После локального PoC запись перенесена в GitHub Actions. Статическая форма подготавливает Issue в целевом repository, пользователь подтверждает его в GitHub, одноразовая action вызывает общие DocumentService/GitHubService и создаёт PR. Аутентификацию выполняет GitHub; допускается только author_association=OWNER. Проверяется совпадение проекта из sources.yml с GITHUB_REPOSITORY.

Пакет server теперь также служит библиотекой validation/service кода для action; HTTP-процесс в опубликованной архитектуре не запускается. Описанный ниже Fastify adapter сохранён как необязательный альтернативный режим. Основной frontend к нему не обращается.

Для синхронизации без долгоживущих секретов используется проверка SHA раз в 15 минут. Короткоживущий GITHUB_TOKEN каждого repository может писать только в этот repository. Ни одного личного токена в frontend или Actions secrets не сохраняется. Цена отсутствия своего сервера — дополнительное подтверждение Issue в GitHub, асинхронный результат в комментарии и ограничение размера Issue.

## Владение документацией

Канонический источник — docsPath в repository команды. Копии не коммитятся в портал: это исключает конфликтующие версии, лишние PR синхронизации и ошибочное редактирование производного файла.

Docusaurus является представлением. Он читает готовое дерево, строит маршруты и sidebar. Ни Docusaurus, ни GitHub Pages не владеют исходными документами.

Один sources.yml используется сборщиком и backend. Frontend получает публичный список из manifest при сборке и актуальный список разделов из API. Проверка принадлежности проекта и путей выполняется повторно на сервере.

## Запись и границы доверия

Статический frontend не может хранить PAT. Backend сопоставляет projectId с серверной конфигурацией и вызывает Octokit.
GitHubService реализует GitHubPort; credential provider можно заменить выдачей installation token GitHub App без изменения document service.
Auth preHandler отделён от маршрутов. В production он обязан устанавливать личность, проверять проектные роли, вести аудит и ограничивать частоту запросов.
CORS не является механизмом авторизации.

main из UI не изменяется: отдельная ветка сохраняет audit trail и позволяет review, проверки и merge правилами GitHub.
GitHub adapter повторно запрещает ветку вне docs/add-* или docs/edit-*.
Токен не помещается в clone URL. Для приватного чтения используется http extraheader через окружение дочернего git, временный clone удаляется.

## Конфликты и гонки

Редактор запоминает blob SHA. При сохранении сервис получает commit main, сравнивает файл из этого commit с expectedSha и создаёт ветку от проверенного commit.
Перед мутациями повторно проверяется main; изменение файла даёт конфликт, изменение другого файла — предложение повторить запрос.
Атомарной транзакции между чтением main и GitHub createRef нет. main может измениться после последней проверки, но commit всё равно делается в отдельной ветке. Такой PR основан на сохранённом снимке; актуальность и конфликты окончательно проверяются при merge правилами GitHub.
Никакая попытка API не перезаписывает main.

GitHub mutations не являются транзакцией. При ошибке PR может остаться ветка с commit. Backend логирует её имя; пользователь может восстановить работу.
Нет распределённой блокировки или постоянного idempotency storage: две отправки до merge могут создать два PR.

## Снимок сборки

Каждый clone shallow, конкретный SHA сохраняется. Между проектами нет общего atomic snapshot.
Repository_dispatch — сигнал пересобраться, а не инструкция checkout произвольного payload ref.
Сборщик не доверяет payload как пути, owner или исполняемой команде.
Manifest содержит SHA, dirty и хеши всех файлов. CI требует чистый commit, локальная работа допускает незакоммиченные документы с явной маркировкой.

Сначала скачиваются все обязательные источники; затем заменяется generated-docs. CI проверяет exit code и не публикует неполный результат.
Common копируется из текущего checkout. Благодаря этому PR самого портала может проверять свои изменённые общие страницы.

## Markdown и пути

Предпросмотр react-markdown не выполняет HTML/JS. Создаваемые файлы имеют расширение .md и парсятся Docusaurus как Markdown.
MDX разрешён только как доверенный исходник, редактируется в GitHub и требует code review.
Frontend title может отличаться от H1: backend не редактирует body за автора.
Существующий frontmatter при edit сохраняется; новые произвольные метаданные из content не принимаются.
Пути формы ограничены ASCII-сегментами. Имена и текст страниц могут быть русскими.
Каталоги с картинками не считаются разделами, пока в них нет Markdown.
Сборщик сохраняет относительную структуру, отказывается копировать symlink. Межпроектные относительные ссылки автоматически не переписываются: используйте маршруты портала или явно согласованные ссылки.

## Production backlog

1. GitHub App, SSO и проектные роли в auth middleware.
2. HTTPS и отдельный защищённый backend deployment, rate limit, audit actor.
3. Состояния операций и идемпотентные повторы PR; мониторинг незавершённых веток.
4. Required checks/reviews на main, обновления зависимостей, pin actions по SHA.
5. Управление секретами вне .env, ротация, ограничение доступа к private docs.
6. При больших repositories заменить recursive tree целевым обходом; сейчас truncated tree выдаёт ошибку.
7. Snapshot/rebuild UI по manifest и политика жизненного цикла документации.

Намеренно нет БД, OAuth, очередей, Kubernetes или внешнего поиска: для проверки распределённого владения документами они не нужны.
